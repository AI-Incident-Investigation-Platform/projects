# projects и требования продукта

Сверка с документацией продукта
([AI-Incident-Investigation-Platform/docs](https://github.com/AI-Incident-Investigation-Platform/docs)),
редакция baseline v3 с машинными контрактами в `contracts/`.

Статусы: **есть** — реализовано; **частично**; **нет** — не начато;
**расходится** — сделано иначе, причина рядом.

## Проекты, окружения, сервисы — 05 §3, §10 B-02, `main-public.openapi.yaml`

| Требование | Статус | Комментарий |
|---|---|---|
| Проекты: список своих, создание, чтение, изменение | есть | |
| `slug` проекта уникален | есть | |
| Архивация проекта (`archived_at`) | нет | поле в ответе всегда `null` |
| Окружения: список, создание, изменение; `slug` уникален в проекте | есть | |
| Сервисы: список с фильтром по окружению, создание, чтение, изменение; имя уникально в окружении | есть | |

| `GET /projects/{id}/topology` | нет | P1 |

## Доступ — `contracts/AUTH_BOUNDARY.md`, 05 §9, 02

| Требование | Статус | Комментарий |
|---|---|---|
| Токен проверяется сервисом по JWKS: подпись, `alg`, `iss`, `aud`, срок | есть | |
| Отзыв сессии — по пропуску в Dragonfly, кэш недоступен — отказ | есть | |
| CSRF — `Origin` у изменяющих запросов | есть | |
| Создатель проекта — owner; глобальных ролей нет | есть | |
| Не участник — `404`, участник без права — `403` | есть | |
| Встроенные роли и права | есть | см. [design.md](design.md#роли-и-права) |
| Участники: список, смена роли, исключение, выход; роли — список | есть | правила назначения — [design.md](design.md#роли-и-права) |
| Приглашение участника | расходится | зовут зарегистрированного пользователя по `user_id` (найден в `users`), а не любой email; он принимает сам. Решение пользователя 2026-10-30, контракт обновлён |
| Права для других сервисов в Dragonfly | есть | `GET /internal/v1/acl` со служебным токеном `auth`, запись после commit, см. [design.md](design.md#права-для-других-сервисов) |
| API-токены проекта (`X-Ingest-Key`): выпуск с показом один раз, хранение хэша, привязка к окружению, отзыв | есть | проверку токена при приёме алертов делает сервис приёма; `last_used_at` пока не заполняется |
| Аудит изменений ролей и участников | нет | |
